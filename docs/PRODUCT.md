# Prompt DJ — продукт и бэклог

> Канон продуктовых приоритетов после MVP (этапы 0–6 ✅).  
> Инженерный чеклист: [DEVELOPMENT.md](DEVELOPMENT.md). Качество пайплайна: [PLAYLIST_QUALITY.md](PLAYLIST_QUALITY.md).  
> Обновлено: 2026-09-18.

## Вердикт

Рабочий **productized MVP** с закрытым value loop «промпт → плейлист в Яндексе». Это уже не прототип, но ещё не бизнес: нет каналов роста, метрик поведения и модели денег.

**Следующий скачок** — не «ещё фичи пайплайна», а **feedback loop + канал (бот) + персонализация от listening graph**.

---

## 1. Суть

| | |
|---|---|
| **Job-to-be-done** | «Описать ситуацию/настроение словами → получить готовый плейлист там, где я слушаю» |
| **Дифференциатор** | Интерпретация намерения (LLM) + семантика (E5) + export в аккаунт Яндекса + итерация без повторного LLM |
| **Каталог** | Только Яндекс Музыка |
| **Монетизация** | Не заложена |
| **ICP (старт)** | Русскоязычный слушатель Яндекса с ситуативными запросами, которому лень собирать вручную |

Сегменты (приоритет сверху вниз):

1. Power listener Яндекса (работа / поездка / быт)  
2. Occasional «себе на кухню» (вирусный вход через удачный промпт)  
3. Контент-продюсер / стример — позже (нужен шаринг и polish)

## 3. Success metrics

| Роль | Метрика |
|------|---------|
| **Primary** | Доля пользователей с ≥1 повторным действием за 7 дней (реген / новая генерация) |
| **Quality proxy** | Like/dislike в UI; listen/skips в Яндексе — если API даст |
| **Guardrail** | p50/p95 latency; `clean ≥ 40`; `selected == N` на situational golden (named-artist full_n + like — см. [PLAYLIST_QUALITY.md](PLAYLIST_QUALITY.md) § Like/dislike) |
| **Secondary growth** | Шаринг ссылки / `?prompt=` из галереи |

Граница качества: **«достаточно хорошо, чтобы слушать целиком»**, не редакционный уровень. Не раздувать regex-войну под промпт/жанр.

---

## 4. Стратегические решения

| Вопрос | Решение |
|--------|---------|
| Multi-catalog (Spotify…) vs глубже в Яндекс | **Сначала глубже в Яндекс** (likes / recent). Multi-catalog — другой продукт |
| Growth | Дешевле всего: **Telegram-бот** + галерея промптов → `?prompt=` |
| Монетизация | Пока рано; тест: freemium N/день, Pro = BPM/lyrics/больше N. **Не** монетизировать «Ещё вариант» агрессивно |
| Что не делать сейчас | Multi-catalog, org-mode, перепись UI, редакционка, regex под каждый жанр |

### P2 — pain и polish

| # | Доработка | Scope | Статус |
|---|-----------|-------|--------|
| P2.1 | **Lyrics**: «без слов» / NSFW (`tracks_lyrics`) | Soft filter, не default hot path | [x] |
| P2.2 | **AI-обложка** плейлиста | Шаринг / polish в Prompt DJ; **не** в Яндекс (см. [API.md](API.md) § cover, [YANDEX_MUSIC.md](YANDEX_MUSIC.md) § export) | [x] |
| P2.3 | Шаринг «промпт + ссылка» с UTMs / deep link | Secondary growth | [x] |

| P2.5 | Мягкий показ latency/cost («~12 сек; Ещё вариант — без LLM») | Ожидания UX | [x] |

### P3 — по триггеру

| # | Доработка | Триггер |
|---|-----------|---------|
| P3.1 | BPM (`librosa`) reorder | Workout/dance + флаг; не в default hot path |
| P3.2 | Celery/Arq | p95 ≫ 20 сек или очередь бота |
| P3.3 | Hard rate-limit Яндекс + backoff UX | Частые 429 |
| P3.4 | Freemium / Pro | Есть спрос и метрики P0 |
| P3.5 | White-label / B2B | Появился B2B запрос |

### Не сейчас

- Multi-catalog (Spotify и т.п.)
- Org-mode / команды
- Перепись UI с нуля
- Редакционный уровень качества
- Агрессивная монетизация «Ещё вариант»
- Regex под каждый промпт/жанр
- Отдельный этап «починить C4 quality.py» (только при SEO-правке)
- Отдельный этап «rewrite user prompt» как фикс качества (см. [PLAYLIST_QUALITY.md](PLAYLIST_QUALITY.md) § preprocess) — низкий ROI; named-artist бэклог Q1–Q5 там же, не PRODUCT-спринт

## 6. Порядок внедрения

```
Спринт 1–2:  P0.1 → P0.3 → P0.2 / P0.4 → P0.5
Спринт 3–4:  P1.1 (бот) ∥ P1.4 (онбординг) → P1.5 (квоты)
Спринт 5–6:  P1.3 (likes/recent) → P1.2 (галерея промптов)
Далее:       P2.1 lyrics → P2.2 обложка → P2.4 replace track
По триггеру: P3.x
```

Инженерия (C4 `quality.py`, handlers) — по касательной, не отдельный продуктовый этап. См. [DEVELOPMENT.md](DEVELOPMENT.md) § «Техдолг».

## 7. Definition of Done по горизонтам

| Горизонт | «Готово», когда… |
|----------|------------------|
| **Видим продукт** | Есть regen-7d, like/dislike, p95 latency на отчёте |
| **Есть канал** | ≥1 не-web вход (Telegram) генерирует плейлисты |
| **Есть дифференциатор** | Опция «с моей библиотекой» заметно меняет пул vs cold prompt |
| **Можно думать о деньгах** | Квоты + cost-per-gen + понятный Pro-пакет |

---

## 8. Риски (держать в уме)

| Риск | Почему |
|------|--------|
| Vendor lock Яндекс | API, auth, каталог, SEO-мусор, 429 |
| Latency >15–20 сек | Ломает «магию» обещания |
| Качество «на глаз» | Like/dislike в UI; skip в Яндексе — если API даст |
| LLM drift | Другие якоря → другой пул; golden узкий |
| Нет discoverability | Галерея есть; полноценный loop без Telegram E2E |
| Нет экономики | Cost-per-gen в метриках есть; монетизация / Pro — нет |

**Узкий, правильно собранный MVP под JTBD в экосистеме Яндекс Музыки; дальше — metrics → бот → listening graph, иначе навсегда сильный pet-проект.**
